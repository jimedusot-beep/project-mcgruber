# Owner photo review workflow

The owner requested annotation of every uploaded project photo so far and subsequent photos in this thread, followed by inclusion in McGruber. Public inclusion of the project photos is authorized in the conversation. This is a review workflow for subsequent assistant turns, not an unattended upload service.

1. Inspect every new source photo. Assign a stable photo ID and retain its uploaded name.
2. Compare bytes and photographed subjects against existing records. Exact duplicate uploads are aliases; different views of the same part remain distinct evidence without increasing part quantities.
3. Add a title and visible-part labels. Put `?` on unresolved identity, hidden markings, wavelength, or inferred function. Describe observable features separately from hypotheses.
4. Keep donor groups separate. IMG_9308–IMG_9317 are the owner's mouse batch; the exterior label reads HP X3000 G2 / G66. Earlier R-NZ remote photos remain a separate donor. Do not assert every historic photo belongs to the mouse.
5. Preserve source copies separately from annotated derivatives. Omit EXIF/GPS metadata from published copies; keep photo markings and original scenes intact. Use deterministic SVG annotations that embed the original JPEG unchanged; never use AI-reconstructed parts as inventory evidence.
6. Correct prior identifications explicitly when a readable marking resolves them. Examples: PIC16F57-E/SP in IMG_9297; MF301 terminal block in IMG_9307. Preserve unresolved claims as unknown.
7. Update owner-photo-identifications.json, the CSV, photo guide, web gallery and relevant BOM evidence links. Verify every photo and part link, hashes, duplicate handling, and browser image loading before publishing.
8. Ownership / photo identification never marks an electrical test as passed. Unknown pinouts, component ratings, sensor sensitivity and successful beam detection remain unknown until documented and measured.
